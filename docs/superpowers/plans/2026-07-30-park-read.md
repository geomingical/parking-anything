# Park Read Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a "Park Read" capture mode for articles, where the model returns a suggested kind from an extensible registry and advises — never forces — a correction when a link looks mis-parked.

**Architecture:** A new `link-kinds.ts` registry is the single source of truth for every kind-dependent string, colour, AI framing and field label. `read` reuses `ai_tool`'s exact field shape, so the Zod change is a third union variant with no storage migration. The model returns `suggestedKind` + `kindRationale`, which `analyzeUrl` lifts out of the stored analysis into a separate `classification` block.

**Tech Stack:** Next.js 16 (App Router), React 19, Zod 4, Tailwind 4, Vitest + Testing Library, Playwright, OpenAI Responses API with `zodTextFormat` structured output.

**Spec:** `docs/superpowers/specs/2026-07-30-park-read-design.md`

## Global Constraints

- TDD is mandatory: write the test, run it, watch it fail for the right reason, then implement. Never write production code first.
- Storage `version` stays `2`. No migration. `storage-v1.ts` must not be touched.
- `suggestedKind` and `kindRationale` must never be stored on a `ParkingItem`. `ParkingItemSchema` is `.strict()` and the client builds items by spreading `analysis`, so a leaked field throws at park time.
- Kind accent colours must not reuse `--safety` (reserved for the attention/review state), `--garage` or `--scrap` (each already means both a status and an action).
- Only animate `transform` and `opacity`. Any new pressable element gets the existing `pressable` class.
- Existing accessible names must not change: `Park tool`, `Park idea`, `Analyze & Park`, `Park Idea`, `AI tool URL`, and every `"{title}, {Status}"` card label. Tests depend on them.
- The mis-park advisory never blocks a park.
- Shared lifecycle copy becomes kind-neutral rather than templated per kind.
- Run `npx vitest run --dir src` for unit tests. `npm run lint` and `npx playwright test` must stay green.

```ts
// src/lib/parking/link-kinds.ts
import type { EffortTier, ParkingItem } from "./schemas";

/**
 * URL-based parkable kinds. `idea` is deliberately absent: it has no URL, so
 * content analysis can never reclassify it.
 */
export const LINK_KIND_IDS = ["ai_tool", "read"] as const;
export type LinkKindId = (typeof LINK_KIND_IDS)[number];

export type KindDisplay = {
  label: string;
  noun: string;
  accentVar: string;
  effortLabels: Record<EffortTier, string>;
};

export type LinkKind = KindDisplay & {
  captureLabel: string;
  framing: string;
  classifierHint: string;
  fieldLabels: {
    summary: string;
    suggestedTestTask: string;
    usefulnessHypothesis: string;
  };
};

export const LINK_KINDS: Record<LinkKindId, LinkKind> = {
  ai_tool: {
    label: "Tool",
    noun: "tool",
    captureLabel: "Park tool",
    accentVar: "--kind-tool",
    framing:
      "Turn one saved AI-tool URL into a concrete evaluation ticket. Describe what the tool appears to do, estimate realistic trial effort, and propose one specific test that can begin in 15 minutes.",
    classifierHint:
      "software you would operate: an app, service, API, model, or library",
    effortLabels: {
      quick_spin: "Quick spin",
      focused_session: "Focused session",
      weekend_project: "Weekend project",
    },
    fieldLabels: {
      summary: "What it appears to do",
      suggestedTestTask: "First test task",
      usefulnessHypothesis: "Usefulness hypothesis",
    },
  },
  read: {
    label: "Read",
    noun: "read",
    captureLabel: "Park read",
    accentVar: "--kind-read",
    framing:
      "Turn one saved article URL into a concrete reading ticket. Describe what the piece appears to argue, estimate realistic reading effort, and propose one specific question the read should answer.",
    classifierHint:
      "prose you would read for understanding rather than operate: an article, blog post, paper, essay, or narrative documentation page",
    effortLabels: {
      quick_spin: "Skim",
      focused_session: "Careful read",
      weekend_project: "Long read",
    },
    fieldLabels: {
      summary: "What it appears to argue",
      suggestedTestTask: "Question this should answer",
      usefulnessHypothesis: "Why it may be worth the time",
    },
  },
};

const IDEA_DISPLAY: KindDisplay = {
  label: "Idea",
  noun: "idea",
  accentVar: "--kind-idea",
  effortLabels: {
    quick_spin: "Quick spin",
    focused_session: "Focused session",
    weekend_project: "Weekend project",
  },
};

export function isLinkKind(value: string): value is LinkKindId {
  return (LINK_KIND_IDS as readonly string[]).includes(value);
}

export function displayFor(kind: ParkingItem["kind"]): KindDisplay {
  return isLinkKind(kind) ? LINK_KINDS[kind] : IDEA_DISPLAY;
}
```

```ts
function buildSystemPrompt(kind: LinkKindId): string {
  const options = LINK_KIND_IDS.map(
    (id) => `- ${id}: ${LINK_KINDS[id].classifierHint}`,

  return `${LINK_KINDS[kind].framing}

Do not invent hands-on evidence or claim the user has adopted or finished it.
Then classify what this link actually is, choosing exactly one id:
${options}
Put that id in suggestedKind and one short sentence of evidence from the source in kindRationale. If the source matches ${kind}, still return ${kind}.`;
}
```

```ts
export async function analyzeUrl(

  dependencies: AnalyzeUrlDependencies = {},

  const kind = request.kind ?? "ai_tool";
  // ...unchanged validate/fetch block, using request.url in place of input...

  const response = await responsesParse({
    model: dependencies.model ?? process.env.OPENAI_ANALYZE_MODEL ?? "gpt-5.6-luna",
    input: [
      { role: "system", content: buildSystemPrompt(kind) },
      { role: "user", content: delimitedSource },
    ],
```

```ts
  /*
   * Rebuilds the item in the store rather than accepting a caller-built one:
   * mutateItem takes any ParkingItem, so nothing else could guarantee that id,

  function reparkItem(
    id: string,
    input: { kind: LinkKindId; analysis: AnalyzeUrlResult },
  ): ActionResult {
    return mutateItem(id, (item) => {
      const terminal = refuseIfTerminal(item);
      if (terminal) return terminal;

          ok: false,
          message: "Only items parked from a link can be re-parked as another kind.",

        ok: true,

        // valid item. commitItems revalidates before anything is written.
        item: {
          ...item,
          ...input.analysis,
          kind: input.kind,
          updatedAt: now,
          lastActivityAt: now,
        } as ParkingItem,
      };
    });
  }
```
